# relay-cache-check

一个命令行的中转站 prompt cache 体检。跑一次，告诉你这条通道**到底缓不缓存、计价老不老实、后端是不是它说的那个**。

```bash
node cache-check.js \
  --url https://你的站/v1 \
  --key sk-xxxx \
  --model "你的模型标签" \
  --prefix-file ./my-system-prompt.txt
```

## 先说三件事

**一、它会真的花钱。** 默认打 8 发左右探针，几毛钱量级（我们实测 $0.33～$0.42 一次）。
跑完会报**实际**花了多少 —— 不是估的，是读站子自己的账单计数器前后差值。

**二、它只发探针、只读回执，不往你的系统里写任何东西。** 最坏的结果是读数错了。

**三、🔴 它自己出过 23 个 bug，形状都写在
[主文档 §8.3](../README.md#83-这个按钮自己出过的-23-个-bug) 里，去看一眼再信它的数字。**
其中最常见的一族是「把『我没测出来』说成『我测出来是坏的』」——
如果哪一次它给你一个很确定的坏消息，先确认探针是不是真打出去了。

## 这不是重写

这是从一个跑了两周的私人网关里**抠出来**的那段，不是照着记忆重写的。
重写会补全，补全会编 —— 而这个仓库唯一的卖点是不说没验证过的话。

抠出来之后只改了三处，都是必须改的：

| 原来 | 现在 |
|---|---|
| 读作者自己库里的人格块+摘要当探针前缀 | `--prefix-file` 你自己的 |
| 读作者自己库里的真实用量 | `--usage-file`（可选），不给就**明说这块跳过了** |
| 读网关记的前缀指纹环 | `--fp-ring`（可选），不给就明说跳过了 |

**验收是这么做的**：抠完在同一条通道上跑了一次，
跟同一天从 app 里那个按钮截出来的报告逐格对 ——
省 89%、虚高 3.6 倍（6067 字符算成 24920 token）、掺水（id 里带 gemini）、
「开着扩展思考所以不能强制调工具」，**全部对得上**。

## 参数

| 参数 | 说明 |
|---|---|
| `--url` | 站的地址。`/v1`、`/v1/chat/completions`、`/v1/messages` 都行，内部一律归一到 `/v1/messages`。🔴 **走 OpenAI 那个门会把 `cache_control` 静默吞掉** |
| `--key` | API key |
| `--model` | 模型标签，**照抄站子给的那一串**（折扣倍率、`次`/`量` 这些字会影响结论） |
| `--prefix-file` | **强烈建议给。** 你真实的系统提示词。不给就退回 8k 填充文字，而「这个玩具能缓存」不等于「你六万八的负载能缓存」 |
| `--usage-file` | 可选。真实用量样本，JSONL，每行 `{"in":…,"cw":…,"cr":…,"model":…,"url":"host","ep":0,"stream":1}` |
| `--fp-ring` | 可选。前缀指纹环（JSON 数组） |
| `--no-stream` | 只测非流式（默认两条都测）|
| `--no-thinking` | 关掉扩展思考。**默认是开的** —— 开不开会改变行为：Anthropic 不允许「强制调工具 + 扩展思考」同时成立 |
| `--endpoint-tools` | 标记为「端点清单」模式（只影响归档口径） |
| `--json` | 只输出 JSON |

## 它测什么

流式/非流式各自缓不缓存 · 真实用量 · 前缀稳不稳 · 扩展思考 · 有没有更新版本 ·
计价老不老实 · 血统（后端是不是它标称的那个）· 会不会调工具 · 本次实际花费
· 外加一块「该怎么选」。

每一块背后是一次真踩过的雷，对应主文档的哪一节都标着。

## 你要是把它包成按钮

**那两道闸必须补回去**（命令行跑一次就是一次，不需要；接口不一样）：

1. 防重复的闸设在**花钱那一端**，不是按钮上 —— 客户端的 `disabled` 挡不住，
   状态一重建就复位，在途的请求还活着。
2. 锁要配一个**自动开的闸** —— 中途抛异常时解锁那行走不到，
   之后每次请求都在等一个永远不会回来的 Promise。

细节见主文档 §7。
